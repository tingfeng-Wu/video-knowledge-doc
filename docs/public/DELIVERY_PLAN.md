# 2027年1月系统交付方案

修订日期：2026-11-03。状态：用户已接受的范围与排期调整；新增能力尚未实现。

## 目标与范围

2027年1月交付功能完整、可安装、可演示的知识型视频讲义生成系统，完成软件著作权申请所需的代码、说明书、截图和演示材料准备。项目以工程交付为主，保留研究探索，不以论文或最优算法指标为目标。正式大创题目暂不修改；申报题目与最终结项口径由负责人向导师核实，软件交付按本方案推进。

重点使用场景为带PPT的中文课程。演讲、报告、知识解说保留为扩展与困难样例，已有结果和失败记录继续保存。主系统无需安装RL依赖、持有PPO模型或完成算法对照实验即可验收。

## 一、交付优先级

| 优先级 | 范围 | 验收要求 |
|---|---|---|
| 必须 | 视频导入、任务列表、进度和错误提示 | 用户能创建任务、知道当前阶段和失败原因 |
| 必须 | ASR、分章、正文、章节配图与时间索引 | 至少有经检查的真实端到端案例，困难样例明确失败或降级 |
| 必须 | 章节与图文预览，JSON/Markdown/Word导出 | 三格式主要内容一致，图片和图注可用，Word逐页检查 |
| 必须 | 缓存、有限调用预算、故障恢复和结果保护 | 重复任务复用产物，失败不覆盖成功结果，调用不越授权 |
| 必须 | 第二台机器复现、安装说明、演示与材料整理 | 按文档安装并走完主要流程，使用自己的输入和凭据 |
| 有限增强 | VLM章内图文生成 | 固定样例显示实际视觉补充，错误和成本可接受后决定纳入正式路径 |
| 有限增强 | 修改标题与正文、删除不合适配图 | 简单表单即可；保存独立人工编辑版本，不改写机器正式组 |
| 独立探索 | 候选边界、规则、PPO及对照 | 如实记录实际完成程度，任何一项未完成均不阻塞主软件 |
| 后置 | VLM分章、复杂富文本、动作/连续动画理解、字幕直提、账号、云部署、协同编辑 | 不进入本轮1月交付范围 |

预览和下载属于必须项；编辑增强只有在稳定性与排期允许时接入。SQLite可用于任务索引，文件仍保存到任务目录；不引入额外数据库或复杂前端构建链。

## 二、保留现有架构，有限改变章内生成

```text
视频 → 媒体检查 / 音频提取 / ASR → 带时间戳文本
  └→ 候选帧 / 页面变化 / 可选OCR → 图片与时间信息
                  ↓
          现有文本LLM初步分章
                  ↓
       保留ASR正文路径；新增可选VLM模式
                  ↓
       章内ASR + 少量图片 → 正文、图注、来源
                  ↓
         检查 → 预览 / 基础修改 → 导出
```

继续复用ASR、统一时间轴、分章、章内选帧、缓存和导出模块。VLM直接承担章内内容生成，使用现成模型推理，不训练或微调视觉模型。第一版不新增独立视觉解析流水线或复杂视觉证据Schema，不同时修改章节算法。

供模型理解的图片与最终展示图片分开控制，参考现有候选并按需补少量均匀覆盖帧；先验证漏图问题，不重开旧页面变化参数网格或改写历史帧集。重点处理静态课件、图表、公式、代码，遇到模糊或不确定内容明确保留不确定性。

ASR路径继续作为稳定模式和参照。只有经过验证的模式可成为默认路径；VLM失败时明确提示，按用户选择或事先批准的降级政策继续ASR路径，不静默切换模型、扩大请求量或覆盖结果。

## 三、先审查生成约束，再实施兼容修复

当前正文要求每个来源单元恰好引用一次，EXPLAINER01因重复引用未发布。下一步先离线检查原始响应，区分来源误用、实际重复与合理多次引用，不直接放宽全部校验。

修订方向：保留来源存在、章内归属、时间与来源可追溯等硬检查；允许经过定义的一个来源支持多个段落；分别检查正文重复、重要遗漏、事实变形和图文对应。新规则实施前确定版本与兼容边界，旧组按其原规则复验。引用覆盖不直接等同于知识完整或事实正确。

本方案不等于已经批准代码中的validator放宽；该变更须通过下一小任务的离线证据与明确设计落地。未审阅的失败正文不视为正确结果。

## 四、VLM投入与停止条件

预留约一周主动开发和验证的投入窗口，不承诺一周必然完成。实施前记录所用模型、图片数量/尺寸、输入范围、请求硬上限、费用边界、超时和缓存策略。窗口结束时检查：

1. 是否补充了ASR未充分表达的重要图文信息；
2. 是否引入明显图表、数字、符号误读或无依据推断；
3. 人工修改负担与调用成本是否可接受。

先使用少量固定样例、相同文档要求，按视频成对比较ASR路径与VLM路径，检查时隐藏模式名称；按视频汇总，不将同视频的多个章节当成独立视频。结论限于该批样例，不宣称普遍优势。停止条件与调用预算须在执行前确定，不能看结果后反复换判据追求成功。

窗口用尽或未显示明确收益时，保留探索结果，正式软件继续稳定路径。后续扩大投入须重新决定，不自动增加模型、供应商、场景或试验规模。

图片外发未包含在既有文本授权中。本次方案调整不授权付费调用或发送图片；实际执行前需用户单独批准数据范围、提供方和有限预算。此前失败即停的请求授权保持原边界，不自动恢复。

## 五、强化学习及数据工作的定位

RL作为独立探索保留，可继续使用候选边界KEEP/DISCARD、低维特征、边界奖励和章节长度约束。研究投入仍以20—30小时主动开发为止损线；不扩展到选帧、OCR调用、正文生成或联合多任务调度。

只有真实训练才报告已训练，只有完成保存/加载与未见视频推理才报告该闭环，只有实际生成文档才报告系统接入。可选择PPO模式的界面仅在真实接通后显示。PPO效果普通或探索未完成时，记录原因与后续计划，不阻塞软件交付。

规则、候选生成、正式15视频的标注和8/3/4划分不再作为Web或软件交付的前置。15视频保留为系统测试目标，记录来源、时长、成功/失败、耗时和导出质量；不足15时明确已测数量及缺口，不冒充完成。开展真实模型训练前，仍须先固定相应标注、数据划分、奖励和评价协议，禁止用测试集调参。

## 六、时间安排与闸门

以下为工作顺序，具体中期日期待确认；1月为交付窗口，12月底争取功能冻结，1月保留复验和材料修正时间。

| 时间 | 工作 | 退出条件 |
|---|---|---|
| 中期前 | 审查并修复现有失败、检查已有文档、第二台机器复现、准备演示与材料 | 稳定缓存演示、真实案例及清楚的失败边界；新LONG01 Word完成逐页检查 |
| 中期后至11月底 | 限时验证章内VLM | 决定纳入稳定模式或保留探索，记录收益、错误与成本 |
| 12月上半月 | 最小FastAPI/Web、任务状态、预览与下载，按余量做基础修改 | 普通浏览器能走完主要流程，CLI与Web调用同一核心服务 |
| 12月下半月 | 多视频检查、修缺陷、安装与使用说明 | 功能冻结候选版、已知问题清单及可复现测试记录 |
| 2027年1月 | 完整复验、第二台机器确认、演示与软著材料整理 | 可交付软件及对应代码/说明/截图/演示，尚未完成的探索明确列出 |

RL只在主线进度允许且数据/协议准备完成时开展，不能挤占12月收口窗口。中期演示前预留冻结和排练时间，不临时切换未验收模式。

主软件闸门为：稳定链路与文档质量、VLM取舍、浏览器闭环、发布候选与最终交付。历史G1—G5的证据和结论保留；与正式训练有关的审核继续适用于实际开展的探索，但不再构成Web和软件交付的全局前置。

## 七、团队协作与完成标准

核心生成链由一名主负责人统筹；其他成员可并行负责第二台机器安装、正文与图文质量检查、视频核验、章节试标、普通缺陷和中期材料。认领前说明输入、交付物及验收方法，再通过Issue/PR协作，不默认任何成员已经接受任务。

软件完成要求：主要流程可复现、正常输入产出可检查文档、异常有可操作提示、预算与凭据安全、导出经检查、安装说明可复现、已测规模与未验证项清楚。任何测试通过数量都不替代真实文档质量。正式题目或学校材料要求如有差异，由负责人确认并记录，不能把软件交付完成直接等同于学校已批准结项。
